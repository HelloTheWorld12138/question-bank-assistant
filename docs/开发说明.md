# 开发说明

本文面向需要运行测试、修改代码或构建桌面包的开发者。教师用户可直接从
[GitHub Releases](https://github.com/HelloTheWorld12138/question-bank-assistant/releases/latest)
下载桌面版本。

## 环境

- Python 3.10+
- macOS、Windows 或 Linux 可运行本地开发服务
- macOS 构建脚本只能在 macOS 运行
- Windows 构建脚本只能在 Windows PowerShell 运行

创建环境并安装开发依赖：

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

Windows PowerShell 使用：

```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
```

## 启动与测试

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
python -m pytest
```

测试通过环境变量使用临时目录，不应修改正式题库。

## 运行时目录

默认情况下，源码运行会使用仓库中的 `vault/`、`exports/` 和 `logs/`。开发或测试时
可以覆盖：

```text
QUESTION_BANK_DATA_DIR
QUESTION_BANK_EXPORT_DIR
QUESTION_BANK_LOG_DIR
```

这些目录里的教师数据、导出文件、设置、日志和备份不会提交到 Git。

## 可选工具

### Pandoc

Word 导入与导出需要 Pandoc。程序优先使用应用内的
`tools/pandoc/pandoc.exe`（Windows）或 `tools/pandoc/pandoc`（macOS），开发环境未提供
内置文件时再检查系统 `PATH`。发布构建会下载固定版本、校验 SHA-256，并在打包后实际完成
一次 Markdown → DOCX → 文本的往返测试。

macOS 发布包同时包含 `third_party/mathtype_to_mathml/`，并在打包阶段使用系统 Ruby 实际
加载转换器。公式依赖无法加载时，构建直接失败，不再生成仅能保留公式图片的安装包。

### PaddleOCR

教师端批量导入只接受 `.docx` Word 文件，不接收 PDF、扫描件或照片。以下依赖仅供保留的
实验性图像文字识别代码和开发调试使用，不属于当前教师端导入流程。

基础依赖不包含 PaddleOCR。需要离线文字识别时安装：

```bash
python -m pip install -r requirements-ocr.txt
```

还需按照目标平台选择兼容的 PaddlePaddle 运行时。

### OfficeCLI

OfficeCLI 是可选的 Word 结构校验和预览工具。程序优先读取 `OFFICECLI_PATH`，其次
检查 `tools/officecli/`。缺少 OfficeCLI 时仍会保留 Pandoc 生成的 Word 文件。

Windows 构建机可使用以下脚本下载固定版本并校验 SHA-256：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\download_officecli.ps1
```

Windows 安装包由 Inno Setup 6 生成。`build_windows.ps1` 会下载 Pandoc 和 OfficeCLI，并将
两者置于应用内部；同时会内置 Ruby、Nokogiri 及 MathType 转换器。打包检查不仅核对文件
列表，还会从最终 `_internal` 目录解包固定依赖并实际加载转换器。最终输出为
`dist/题搭子-Setup-版本号.exe`。用户的题库始终保留在
“文档/高中物理题库”，卸载应用不会删除这些数据。

安装器还会检查 Microsoft Edge WebView2 Runtime（桌面窗口所需）。通常 Windows 已自带；
缺失时安装器会联网下载 Microsoft 的运行时。

第三方归属和许可证位于 `third_party/OfficeCLI/`。

## 桌面构建

macOS：

```bash
bash scripts/build_macos_dmg.sh
```

输出为 `dist/题搭子.dmg`。构建脚本会写入 `app/config.py` 中的版本号并进行临时签名；
正式对外分发如需消除 Gatekeeper 提示，还需 Apple Developer ID 签名和公证。

Windows：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_windows.ps1
```

输出为 `dist/题搭子-Windows.zip`。GitHub Actions 中的 `Build Windows package`
工作流可以在 Windows 构建机上执行同一脚本。

## 主要模块

```text
app/api/routes.py           HTTP 路由
app/services/imports.py     Word 批量导入、草稿切分与审核
app/services/questions.py   录题、检索与组卷
app/services/documents.py   Word 转换与结构识别
app/services/models.py      云端与本地模型适配
app/services/maintenance.py 备份、恢复和完整性检查
app/storage.py              Markdown、YAML 与索引读写
desktop.py                  桌面窗口入口
```

题库的字段、正文结构和向后兼容约定见
[数据格式规范](./数据格式规范.md)。

## 发布检查

发布前至少完成：

1. 更新 `app/config.py` 和静态资源查询参数中的版本号。
2. 更新 `CHANGELOG.md`。
3. 运行完整测试。
4. 构建并校验目标平台安装包。
5. 使用版本标签创建 GitHub Release。
6. 为安装包生成并上传 `SHA256SUMS.txt`。
